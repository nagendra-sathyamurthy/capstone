```powershell
# Run with verbose output
.\Run-All-Tests.ps1 -Verbose
```


```powershell
# Run specific collection
newman run user-registration/User-Registration-Flow.postman_collection.json `
  -e Capstone-Local-Environment.postman_environment.json

# Run with data file
newman run user-registration/User-Registration-Flow.postman_collection.json `

newman run restaurant-owner-workflows/Restaurant-Owner-Workflows.postman_collection.json `
```

## 🔐 User Registration Flow Collection

### Overview
The User Registration Flow collection provides complete user registration and authentication workflow for all user roles in the system. It supports registration, login, and token validation with data-driven testing capabilities.

### Collection Structure

#### Requests

**1. Register User**
- **Method**: POST
- **Endpoint**: `{{auth_base_url}}/api/auth/register`
- **Purpose**: Creates a new user account
- **Input**: User data from data files (email, password, role, organization)
- **Output**: User ID (stored in collection variable)
- **Success Codes**: 200, 201, 409 (Already Exists)

**2. Login User**
- **Method**: POST
- **Endpoint**: `{{auth_base_url}}/api/auth/login`
- **Purpose**: Authenticates user and retrieves JWT token
- **Input**: Email and password from variables
- **Output**: JWT token (stored in `auth_token` variable)
- **Success Code**: 200

**3. Validate Token**
- **Method**: GET
- **Endpoint**: `{{auth_base_url}}/api/auth/validate`
- **Purpose**: Verifies JWT token validity
- **Authentication**: Bearer token
- **Success Code**: 200

### Data-Driven Testing

The collection uses external JSON data files for bulk operations:
- Each data file contains multiple user records
- Newman runs the collection once per data record
- Variables populated automatically from data file

### Available Data Files

## 🐛 Common Troubleshooting

### Authentication Issues

**401 Unauthorized**
- **Cause**: Expired or invalid auth token
- **Solution**: Re-login using respective authentication request

**403 Forbidden**
- **Cause**: User doesn't have required role/permissions
- **Solution**: Verify account has correct role and organization

### Service Issues

**404 Not Found**
- **Cause**: Resource doesn't exist or services not running
- **Solution**: 
  - Check if all services are running: `docker ps`
  - Verify variable values (IDs, etc.)
  - Run prerequisite requests first

**500 Internal Server Error**
- **Cause**: Backend service error
- **Solution**: Check service logs: `docker logs capstone-<service>`

### Data Issues

**409 Conflict**
- **Cause**: Duplicate resource (email, etc.)
- **Solution**: This is expected for registration; proceed with login

**400 Bad Request**
- **Cause**: Invalid request body format
- **Solution**:
  - Review request body format
  - Check required fields
  - Validate data types

## 📖 API Endpoints Quick Reference

### Authentication Service (Port 30001)
- POST `/api/auth/register` - Register new user
- POST `/api/auth/login` - Authenticate user
- GET `/api/auth/validate` - Validate JWT token

### Catalog Service (Port 30002)
- POST `/api/catalog/restaurant/register` - Register restaurant
- GET `/api/catalog/restaurant/owner/{ownerId}` - Get owner's restaurants
- POST `/api/catalog/menu` - Create menu item
- POST `/api/catalog/menu/bulk` - Bulk create menu items
- GET `/api/catalog/menu/owner/{ownerId}` - Get owner's menu items
- GET `/api/catalog/menu/restaurant/{restaurantId}` - Get restaurant menu
- PUT `/api/catalog/menu/{id}` - Update menu item
- DELETE `/api/catalog/menu/{id}` - Delete menu item

### CRM Service (Port 30003)
- GET `/api/crm/userprofile/by-user/{userId}` - Get user profile
- PUT `/api/crm/userprofile/by-user/{userId}` - Update profile
- GET `/api/crm/userprofile/by-user/{userId}/addresses` - Get addresses
- POST `/api/crm/userprofile/by-user/{userId}/addresses` - Add address
- PUT `/api/crm/userprofile/by-user/{userId}/addresses/{addressId}` - Update address
- DELETE `/api/crm/userprofile/by-user/{userId}/addresses/{addressId}` - Delete address

### Cart Service (Port 30004)
- POST `/api/cart/{cartId}/items` - Add item to cart
- GET `/api/cart/{cartId}` - Get cart
- DELETE `/api/cart/{cartId}/items/{itemId}` - Remove cart item

### Order Service (Port 30005)
- POST `/api/orders` - Create order
- GET `/api/orders/{orderId}` - Get order details
- GET `/api/orders/customer/{customerId}` - Get customer orders
- POST `/api/orders/{orderId}/cancel` - Cancel order

### Operator Endpoints (Port 30002 - Catalog Service)
- GET `/api/operator/orders/pending/{restaurantId}` - Get pending orders
- POST `/api/operator/orders/{orderId}/accept` - Accept order
- GET `/api/operator/inventory/{restaurantId}` - View inventory
- PATCH `/api/operator/inventory/{menuItemId}/availability` - Update availability
- POST `/api/operator/orders/{orderId}/package` - Package order
- POST `/api/operator/orders/{orderId}/generate-handover-otp` - Generate OTP
- POST `/api/operator/orders/handover` - Complete handover
