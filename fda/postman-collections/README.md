## 🚀 Quick Start

### Run All Tests

**Option 1: PowerShell**
```powershell
.\Run-All-Tests.ps1
```

**Option 2: Batch File (Double-click or command line)**
```cmd
Run-All-Tests.bat
```

**Option 3: Quick Test (for development)**
```powershell
# Test specific workflow
.\Quick-Test.ps1 -Workflow users
.\Quick-Test.ps1 -Workflow restaurants
.\Quick-Test.ps1 -Workflow operators

# Test all workflows (quick version)
.\Quick-Test.ps1 -Workflow all
```

### View Results

After running tests, open the generated HTML reports in `test-results/` directory:
- Double-click any `.html` file to view detailed test results
- Start with `00-test-summary.txt` for an overview

## 🔧 Prerequisites

### Software Requirements

1. **Node.js** (v14 or higher)
   ```powershell
   node --version
   ```

2. **Newman** (Postman CLI)
   ```powershell
   npm install -g newman
   ```

3. **newman-reporter-htmlextra** (for HTML reports)
   ```powershell
   npm install -g newman-reporter-htmlextra
   ```

Ensure all services are running before executing tests:

**Local Environment**:
```powershell

# - capstone-cart (port 30004)

# - capstone-payment (port 30006)
```

## 📖 Usage Examples

### Basic Usage

```powershell
# Run all tests with default settings (local environment, with reports)
.\Run-All-Tests.ps1

# Run against production environment
.\Run-All-Tests.ps1 -Environment Production

# Run with verbose output
.\Run-All-Tests.ps1 -Verbose

# Run without HTML reports (faster)
.\Run-All-Tests.ps1 -GenerateReports $false
```

### Development Testing

```powershell
# Quick test - users only
.\Quick-Test.ps1 -Workflow users

# Quick test - restaurants only
.\Quick-Test.ps1 -Workflow restaurants

# Quick test - operators only
.\Quick-Test.ps1 -Workflow operators

# Quick test - all workflows (no detailed reports)
.\Quick-Test.ps1 -Workflow all -NoReports
```

### Manual Testing with Newman

```powershell
# Run specific collection
newman run user-registration/User-Registration-Flow.postman_collection.json `
  -e Capstone-Local-Environment.postman_environment.json

# Run with data file
newman run user-registration/User-Registration-Flow.postman_collection.json `
  -d user-registration/data/customer-registration.json `
  -e Capstone-Local-Environment.postman_environment.json

# Run specific folder
newman run restaurant-owner-workflows/Restaurant-Owner-Workflows.postman_collection.json `
  --folder "Menu Management - Add Items" `
  -e Capstone-Local-Environment.postman_environment.json

# Generate HTML report
newman run operator-service-workflows/Operator-Service-Workflows.postman_collection.json `
  -e Capstone-Local-Environment.postman_environment.json `
  --reporters cli,htmlextra `
  --reporter-htmlextra-export test-results/custom-report.html
```

## 🎯 Test Scenarios

### User Registration Flow
1. Register user account (Customer, Owner, Worker, Agent, Admin roles)
2. Login with credentials → Receive JWT token
3. Validate token → Verify user info

### Restaurant Owner Workflow
1. **Registration**: Register restaurant with complete details
2. **Menu Management**: Add/update/delete menu items
3. **Status Management**: Activate/deactivate restaurant
4. **Hours Management**: Update business hours
5. **Contact Management**: Update contact information
6. **Address Management**: Update restaurant address

### Operator Service Workflow
1. **Order Management**: View and accept pending orders
2. **Menu Availability**: Update item availability based on inventory
3. **Inventory Management**: Check stock levels, view low-stock alerts
4. **Packaging Management**: Add packaging details and special instructions
5. **Order Handover**: Generate OTP → Verify OTP → Complete handover

## 🐛 Troubleshooting

### Common Issues

#### Newman Not Installed
```powershell
# Install Newman globally
npm install -g newman
npm install -g newman-reporter-htmlextra
```

#### Services Not Running
```powershell
# Check running services
docker ps

# Start services
docker-compose -f docker-compose-local.yml up -d

# Check service logs
docker logs capstone-authentication
```

#### Permission Errors
```powershell
# Set execution policy (run as Administrator)
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser

# Or run script with bypass
powershell -ExecutionPolicy Bypass -File .\Run-All-Tests.ps1
```

#### Test Failures
1. Check service logs: `docker logs <service-name>`
2. Review HTML reports for detailed error messages
3. Verify environment variables in environment file
4. Check test data files for validity
5. Ensure database is seeded with required data

## 🔄 CI/CD Integration

### GitHub Actions Example

```yaml
name: API Tests
on: [push, pull_request]
jobs:
  test:
    runs-on: windows-latest
    steps:
    - uses: actions/checkout@v3
    - name: Setup Node.js
      uses: actions/setup-node@v3
      with:
        node-version: '18'
    - name: Install Newman
      run: |
        npm install -g newman newman-reporter-htmlextra
    - name: Run Tests
      run: |
        cd fda/postman-collections
        .\Run-All-Tests.ps1
    - name: Upload Reports
      uses: actions/upload-artifact@v3
      if: always()
      with:
        name: test-reports
        path: fda/postman-collections/test-results/
```

## 📝 Best Practices

### Before Running Tests
- ✅ Ensure all services are running and healthy
- ✅ Verify environment file is configured correctly
- ✅ Check database is accessible
- ✅ Clear any stale test data if needed

### During Test Execution
- ⏸️ Don't modify services or database
- ⏸️ Don't run manual tests concurrently
- ⏸️ Monitor system resources

### After Test Execution
- 📊 Review test reports for failures
- 📊 Archive reports for historical reference
- 📊 Clean up test data if needed
- 📊 Update test data files as system evolves

## 🤝 Contributing

### Adding New Test Collections

1. Create collection folder under `postman-collections/`
2. Add collection JSON file
3. Create `README.md` with usage instructions
4. Create `TEST-DATA-REFERENCE.md` with test data details
5. Create `data/` subdirectory with test data files
6. Update `Run-All-Tests.ps1` to include new collection
7. Document in this README

### Updating Test Data

1. Modify JSON files in respective `data/` folders
2. Update `TEST-DATA-REFERENCE.md` with changes
3. Run tests to verify changes
4. Commit both data files and documentation
